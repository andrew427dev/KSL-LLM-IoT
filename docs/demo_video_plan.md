# KSL-LLM-IoT 데모 영상 계획

> 제출용 데모 영상의 촬영·편집 계획. 라이브 시연(발표)과 별도로, 현장 실패에 대비한
> 백업 영상이자 "정상 동작" 증빙 자료다. 모든 하드웨어(부저·LED·버튼·LCD) 동작과
> 버튼 로직(완료·undo·문체 전환)을 화면에 명시적으로 담는다.

---

## 1. 확정 문장 (라이브 인식 검증 완료)

세 조합 모두 라즈베리파이 실기에서 90% 이상 신뢰도로 인식됨을 확인했다. 약한 단어
(밥·주다·배고프다·당신 등)는 제외했다. 모든 문장은 트리거어 `완료`로 끝난다.

| # | 수어 순서 | 정중 출력(예상) | 친근 출력(예상) | 영상 내 역할 |
|---|----------|----------------|----------------|--------------|
| 1 | 친구 → 돕다 → 감사 → 완료 | 친구가 도와줘서 감사합니다. | 친구가 도와줘서 고마워! | 메인(인식+LLM+하드웨어 피드백) |
| 2 | 아프다 → 의사 → 돕다 → 완료 | 아플 때 의사 선생님이 도와주십니다. | 아프면 의사가 도와줘. | 문체 전환 시연 |
| 3 | 춥다 → 덥다 → 아프다 → 완료 | 춥거나 더우면 몸이 아플 수 있습니다. | 춥거나 더우면 몸이 아플 수 있어. | undo(단어 제거) 시연 |

출력 문장은 Gemini 생성 결과라 표현이 일부 달라질 수 있다. 본 촬영 전 각 조합을
1회 이상 생성해 실제 출력을 확인한다.

---

## 2. 사전 준비

1. **수어 연습**: 시연자가 위 3문장의 수어 순서를 인식 성공할 때까지 반복 연습한다.
   영상은 재촬영이 가능하므로, 본 녹화 전 각 단어가 안정적으로 잡히는 동작·속도를 확정한다.
2. **RPi 기동** (스트림 포함):
   ```bash
   ssh raspi
   cd ~/Desktop/KSL-LLM-IoT
   setsid env XDG_RUNTIME_DIR=/run/user/1000 PYTHONUNBUFFERED=1 \
     KSL_HEADLESS=1 KSL_STREAM=1 .venv/bin/python src/main.py \
     >/tmp/ksl_demo.log 2>&1 </dev/null &
   ```
   브라우저에서 `http://<RPi_IP>:8080/` 로 인식 화면(카메라+랜드마크+버퍼)을 연다.
   종료: `pkill -9 -f "[s]rc/main.py"` (자기매치 회피용 대괄호 표기).
3. **촬영 셋업** — 2소스 + 인서트:
   - 소스 A(전경): 폰/캠코더 삼각대 고정. 시연자 상반신 + RPi·LCD·LED·버튼·스피커가
     한 프레임에 들어오게. 부저음이 마이크에 잡히게 한다.
   - 소스 B(인식 화면): 맥 브라우저의 MJPEG 스트림을 화면 녹화한다(랜드마크·신뢰도 = 인식 증거).
   - 인서트(별도 촬영): ⓐ LCD 글자 ⓑ LED 점멸 ⓒ 버튼 누르는 손가락.
4. **환경 체크**: python 단일 인스턴스, 조명 정면·균일(LED 점멸이 보이게), 카메라 거리
   40~80cm, Gemini 키·네트워크 정상.

## 3. 영상 구성 (약 75초, 편집 기준)

### ① 인트로 카드 (3s)
제목·팀·"라즈베리파이 단독 실시간 KSL 번역".

### ② 하드웨어 투어 (10s)
RPi → I2C LCD → 부저 → 상태 LED → 버튼 4개(완료/undo/정중/친근) → 스피커 → USB 웹캠을
천천히 팬한다. 각 부품을 자막으로 라벨한다.

### ③ Scene 1 — 인식 + LLM 문장화 + 하드웨어 피드백 (문장 #1, 25s)
| 순간 | 화면 | 하드웨어 |
|------|------|----------|
| 친구·돕다·감사 수어 | A + B(랜드마크) PiP | 인식마다 부저 짧게 1회 + LED 점멸(인서트 ⓑ), LCD 단어·신뢰도(인서트 ⓐ) |
| 완료 버튼 | 인서트 ⓒ | 부저+LED 길게 1회 |
| 출력 | A | TTS 음성(자막) + LCD 영어 문장(인서트 ⓐ) |

### ④ Scene 2 — 문체 전환 + 캐시 재생 (문장 #2, 15s)
- 아프다·의사·돕다 → 완료 → 정중 문장 출력.
- 친근 버튼(부저 2회) → LCD `Style: Friendly`(인서트 ⓐ) → 완료 재누름 → 친근 문장 출력.
- 자막으로 "1회 호출로 두 문체 생성·캐시 → 전환 시 추가 호출 0회" 명시.

### ⑤ Scene 3 — 버튼 로직: undo (문장 #3, 18s)
- 춥다·덥다·아프다 입력 중 일부러 단어를 하나 더(또는 오인식) → undo 버튼(인서트 ⓒ) →
  부저 3회 + LCD 버퍼에서 단어 사라짐(인서트 ⓐ) → 다시 수어 → 완료 → 정상 출력.
- (여유 시) 출력 후 undo 다시 → 길게 1회 → 같은 문체 재생성.

### ⑥ 아웃트로 카드 (4s)
"27/30 단어 안정 인식 · held-out 0.72 · 740KB · 6.4FPS".

## 4. 하드웨어 노출 체크리스트 (전부 1회 이상 화면에)

- [ ] **부저**: 짧게(인식)·길게(완료)·3회(undo) 소리가 영상 오디오에 담김
- [ ] **상태 LED**: 부저와 동기 점멸하는 클로즈업 1컷 이상(접근성 핵심)
- [ ] **LCD**: 단어·신뢰도 / 영어 문장 / `Style:` 표시가 읽히는 클로즈업
- [ ] **버튼 4종**: 완료·undo·정중·친근을 누르는 장면 각 1회 이상

---

## 5. 자막 (영어)

수어 단어, 생성 문장(한국어/영어), 버튼 동작("Complete", "Undo: remove last word",
"Persona: Friendly", "Replay (cached, 0 API calls)")을 자막으로 표기한다.

---

## 6. 편집·컨틴전시

- **재촬영 허용**: 영상이므로 인식 성공 테이크만 사용한다. NG는 재촬영.
- **길이 조절**: 시간이 빠듯하면 Scene 3을 "단어 제거"만(reroll 생략)으로 축소한다.
- **부저·LED 동기 컷 필수**: LED 점멸과 부저음이 동시에 드러나는 클로즈업을 반드시 포함한다.
- **약한 단어 금지**: 밥·배고프다·주다는 도메인 갭으로 제외(보고서 §7.1 한계에서 별도 기술).
