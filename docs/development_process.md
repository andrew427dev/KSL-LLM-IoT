### 1.1 W1 — 프로젝트 스캐폴드 (05-06~07)

- 저장소 구조(`src/`·`config/`·`model/`·`tests/`), 메인 루프·LCD·부저·문장 빌더 골격, PR/이슈 템플릿 (28c1612, e7b37df).
- 1주차 치명 버그 일괄 정리 + 스캐폴드 완성 (f1425d2). GitFlow 변형(feature → develop → main) 채택.

### 1.2 W2 — 스모크 파이프라인과 입력 차원 확정 (05-14~18)

**PR #2 — 하드웨어·모델·API 키 없이 전 구간이 도는 구조.**
- `rpicam-vid` 서브프로세스 카메라 백엔드: Trixie 시스템 Python 3.13에는 mediapipe 휠이 없어 uv로 Python 3.11 venv를 구성했는데, `python3-libcamera`는 시스템 3.13 ABI 전용이라 picamera2를 venv에서 사용할 수 없는 구조적 제약을 서브프로세스 분리로 우회 (HANDOFF §2 2-A~2-F).
- 헤드리스 모드(`KSL_HEADLESS=1`·`DISPLAY` 자동 감지), 분류기 더미 모드 + `make_dummy_model.py` — 데이터 수집·학습 전에 카메라→MediaPipe→분류기→메인 루프를 검증.
- 비동기 파이프라인 (cdb2ac2): Gemini 호출·LCD I2C·부저가 메인 루프에서 동기 실행되어 인식 직후 카메라가 1~3초 정지하던 문제를 워커 스레드 분리로 제거. EOL된 `google-generativeai`를 `google-genai`로 마이그레이션, API 키 부재 시 오프라인 폴백 (345f11e).
- USER_MANUAL.md(운용자용)·CLAUDE.md(문서 갱신 규칙) 신설 — 코드와 문서의 동기화 규칙을 저장소에 내장.

**PR #7 — 양손 전환(63→126차원).** KSL는 양손 언어로 단일 손 입력은 의미 보존이 불가능. 데이터 수집 시작 *전*에 차원을 확정해야 폐기·재수집 비용이 없다는 판단(당시 수집 0건)으로 우선 처리. MediaPipe handedness가 거울 모드(selfie) 가정이라는 동작 원리를 검증해 `cv2.flip` 후 호출 규약을 고정, score 임계·라벨 충돌 재배정 처리 추가 (7e9ae35).

**PR #8 — CI 정적 검증.** settings·augment·hand_tracker 회귀 점검 워크플로.

### 1.3 W3~4 — 데이터 전략 전환과 학습 인프라 (05-19~06-09)

- 카메라 업그레이드 평가: OV5647 3.6mm(FOV 54°)는 인식률 개선 효과가 없고, ToF 카메라는 모델 재학습이 전제라 채택 보류 — 비용 대비 효과 기준으로 기각.
- 손 인식 진단 도구 `check_hands.py` 개발 (PC 폴백 포함).
- GPU 학습 서버 확보 (RTX 4000 Ada 20GB, CUDA 12.7, 컨테이너 메모리 24GB 제한).
- AI Hub 수어 영상 데이터셋 구조 검증: 손 관절 21개×양손 3D 키포인트가 프로젝트 포맷과 호환됨을 확인, `convert_aihub.py` 초판 작성 (d21aeb2) — confidence 폐기, 손목 상대 정규화로 런타임 표현과 일치시키는 변환 설계.

### 1.4 W5 — 131차원·서버 학습·실기 통합 (06-10, 단일일 집중 개발)

- **131차원 전환** (1cf8fcd): 손별 intra-hand scale 정규화(좌표계 단위·거리·손 크기 invariant) + 손목간 벡터 + presence flag. 레이아웃을 `src/feature_format.py` 단일 소스로 — 추론·변환 공유로 train/serve skew 구조적 차단.
- **치명 버그 3종 수정** (6ab6745): sklearn LabelEncoder 유니코드 정렬로 인한 라벨 역매핑 불일치(§3 표 1), TF 2.16+ LSTM TFLite 변환 불가 → 2.15.1 고정 + batch=1 고정 변환, float16 양자화 OOM → 미적용.
- **좌표축 정렬 실측 확정** (6c53d0f): 동일 영상의 MP4(런타임 경로)와 키포인트를 프레임별 비교(725쌍) — x 부호 반전 필요를 수치로 확정 (§3 표 2).
- **GPU 학습 파이프라인** (87a0cdf): 배포→업로드→설정→학습→회수 스크립트 6종, 서버 E2E 검증(18단어 예시 데이터 0.98). AI Hub 서버 직접 다운로드 (8ae5b49 외) — aihubshell의 하위 경로 저장·unzip 부재 함정 처리.
- **물리 버튼 4개 + 페르소나** (8ffdaab): 침묵 트리거(비결정적)를 버튼(결정적·촉각)으로 대체, 비프 1/2/3회 비시각 피드백. Trixie에서 GPIO edge detection 실패 → 폴링 전환 (b66ca06).
- **출력 이중화** (d76e505): 음성=한국어, LCD·GUI=영어 (LCD 한글 미지원 대응).
- **30단어 라벨 전면 개정**: AI Hub 사전 표제어와 정확 매칭 — 어근 매칭의 의미 오염("기다리세요"↔"다리") 실측 후 `--exact` 강제.
- **실기 진단 사이클**: 운용 모델(시연자 3명, 전수 0.95)을 RPi에 배포했으나 실기 인식률 미달 → `diagnose_live.py`(top-3·검출률·VNC 미리보기)로 원인 추적 → 저FPS 시간 왜곡 발견 → **시간 리샘플링** (9c742de, §3 표 3). 스피커 전원 리플 잡음도 실측으로 확정·해결 (4111aec).

### 1.5 W6 — 도메인 갭 정리와 평가 신뢰성 (06-11~)

- 진단에서 남은 패턴(전 예측 확신도 ~1.00, 유사 의미 단어로 쏠림)을 근거로 **학습-런타임 도메인 갭을 전수 정리(G1~G7)** — z축 품질, 시간 정보 밀도, 검출 노이즈, 시연자 분포, 과신, 좌표 비등방성, 조음 위치 결손 (HANDOFF §1.6).
- label smoothing 0.1 + z_jitter 증강 (ddad8f6), 시연자 16명으로 데이터 확대.
- **PR #9 머지 전 다각도 리뷰**: 9개 관점 병렬 검토 + 후보별 검증으로 15건 기록 — G6 비등방성·평가 누출은 이 과정에서만 발견.
